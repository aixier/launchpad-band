# Launchpad Mini MK2 小白玩法:产品设计方案

日期:2026-10-26 | 状态:方案稿,未上机 | 作者:产品经理 agent

## 0. 读我:证据口径

- 设备能力以 `README.md` 与 `docs/launchpad-mk2-programmers-reference-v1.03.pdf`(下称「MK2 手册」)为准。本文引用处写作 `[MK2手册·章节]` 或 `[README]`。
- **本次没有碰硬件、没点灯、没装软件、没改设备目录已有文件。** 所有「实测」都只来自 README 里 2026-10-26 的枚举记录,其余设备行为一律是「按手册推断」,标 `[待验证]`。
- **没有联网核实外部产品/项目。** 文中提到的外部产品、库只凭已有知识,一律标 `[未核实]`,使用前要核实。
- **没有做过任何用户调研。** 第 1 节的三类人是**假设画像**,不是调研结论;所有目标值(如「60 秒内上手」)是**拟定验收线**,不是实测数字。
- 价格、延迟、LLM 猜图命中率:全部没有数据,方案里只给「怎么测」。

### 0.1 设备事实核对(开工前必须知道的三件事)

1. **本机按 MK2 协议(RGB)枚举**:`VID_1235 PID_0069`,总线名 `Launchpad MK2`[README·实测记录]。PID 0x69 对应 MK2 手册里「设备 ID 1」(USB 身份 69h~78h)[MK2手册·Bootloader]。但手册写的是**全尺寸** MK2,Mini MK2 是否完全同协议,README 标为 `[待验证]`。用户任务描述里「RGB 每色 0-63」与手册 SysEx 0Bh 一致,**是否真的点得出 RGB 仍待上机确认**。README 正文里「双色 LED、原版协议、约 400 条/秒」是修正前的旧结论,本方案不采用,只把「速率」当风险项。
2. **按键没有力度**:手册写明按下发最大力度 note-on、松开发力度 0 [MK2手册·Basic Communication]。所以**做不了「弹得轻重」类表现**,这直接影响乐器类玩法的上限。
3. **LED 只写不读**:手册里没有读回灯色的消息,软件必须自己保存「现在每颗灯是什么色」。
4. 实物照片 `photos/top-view.jpg` 是竖拍(像是转了 90°):照片里右侧一列写着 ▶◀▲▼/Session/User1/User2/Mixer,底部一排是 ▽。按 MK2 手册,标这些字的应是**顶排 8 键(CC 104~111)**,▽ 是右侧 8 键(note)。本文一律**按编号**而不是按「顶/右/底」称呼,避免认错。照片里有几颗键帽缺角,上机时要测它们按得灵不灵 [README]。

### 0.2 与手册对应的关键协议速查(Session 布局,通道 1)

| 项 | 内容 | 出处 |
|---|---|---|
| 8x8 主盘 | note = 11 + 列 + 10×行(行从下往上 0~7):左下 11,右上 88 | MK2手册·Layouts(「加 1 右移、加 10 上移」) |
| 右侧 8 键 | 也发 note,推测为 19、29…89 | `[待验证]`(手册编号图为图片,文本未提取) |
| 顶排 8 键 | CC 104~111(68h~6Fh),按下 127、松开 0 | MK2手册·Layouts |
| 设色(调色板) | note-on 力度 = 0~127 号色,0=灭 | MK2手册·Colours |
| 设色(RGB) | SysEx `F0 00 20 29 02 18 0B <LED> <R> <G> <B> F7`,每色 0~63,**一条消息最多重复 80 组** | MK2手册·RGB Mode |
| 全灭 | SysEx `...0E 00 F7` | MK2手册 |
| 切布局 | SysEx `...22 <layout> F7`,0=Session | MK2手册 |
| 闪烁 / 呼吸 | 通道 2 / 通道 3 的 note-on,或 SysEx 23h / 28h;**用的是调色板号,不是 RGB**;节奏跟 MIDI 时钟(默认 120BPM,可发 F8 改 40~240) | MK2手册·Flashing/Pulsing/MIDI Clock |
| 滚动文字 | SysEx `...14 <色> <循环> <文本> F7`,**ASCII 字符**,速度 1~7;结束回 SysEx 15h | MK2手册·Text scrolling |

要点:**滚动文字只有 ASCII,不能显示中文**。所以给小白的中文说明必须走电脑屏幕/语音,不能指望灯盘。

## 1. 用户画像与场景(假设画像,待调研验证)

共同前提(设备约束,非调研):灯盘没有屏幕、没有声音;小白拿到的是一块**会亮的 8x8 格子**,不知道它能干什么,也不知道要不要装软件。

### 画像 A:孩子(假设 7~10 岁),家长在旁边

目标:想玩,不想学。家长想要「不是又一个屏幕」。
**第一次拿到设备的 10 分钟(拟定旅程,以 MVP「灯灯猜猜」为例):**

| 时间 | 发生什么 | 情绪/风险 |
|---|---|---|
| 0:00 | 家长已提前装好(原型阶段由我们预装,见 6.4)。插上,灯盘自己亮起一圈彩虹波纹 | 「它活了」。风险:不亮 = 立刻失去兴趣 |
| 0:10 | 中间一格在呼吸闪,电脑大字:「按一下会发光的键」。孩子戳它 | 零阅读门槛:孩子会戳发光的东西 |
| 0:30 | 格子变色+「叮」,边上亮起一排颜色;孩子乱涂。完成键开始呼吸。按下后灯盘做「扫描」动画,屏幕/语音:「我看到好多红色挤在左边……我猜是:一团火?」(哪怕是乱涂) | 第一次「AI 回应我」。孩子大概率笑,会想再来一次 |
| 2:00 | 出第一道题「画一个:太阳」,孩子画黄圆,AI 猜对 | 成就感;若猜错,AI 的话必须不甩锅给孩子(见 4.6) |
| 5:00 | 孩子想「难倒 AI」,故意画怪东西;家长也加入 | 这是复玩动机的主来源(假设) |
| 8:00 | 屏幕上出现「今天的画册」(每幅画 8x8 缩略图) | 可展示、可给家长看 |
| 10:00 | 孩子自己问「还能画什么?」 | 判断标准:不用人催就继续 |

### 画像 B:不懂音乐的成年人(假设:办公桌/家里,独自玩)

目标:花几分钟放松,或买来/翻出来这块设备想「看看能干嘛」。怕被当成「要学东西」。
| 时间 | 发生什么 |
|---|---|
| 0:00 | 双击启动,灯盘亮起。他本来预期要看教程;没有教程,只有一个会呼吸的键 |
| 0:40 | 完成一次「随手涂→AI 评语」,AI 语气带一点幽默,但**不评价人**,只说它看到什么 |
| 3:00 | 选「每日一题」,10 个题里挑一个画;AI 猜 |
| 6:00 | 他想「AI 能猜我画的 X 吗」,主动挑战开放词(自由模式) |
| 10:00 | 看画册。风险:独自玩的复玩动机弱(假设),要靠「每日一题」和「画册积累」,这是 MVP 要验证的最大不确定性之一 |

### 画像 C:聚会/家庭(3~6 人,假设)

目标:有一个大家围着、不用懂规则、能笑的东西。
| 时间 | 发生什么 |
|---|---|
| 0:00 | 设备放桌子中间,屏幕接电视或大显示器(推荐,见 6.4) |
| 0:30 | 一个人试按,其他人围观。规则只有一句话:「轮流画,大家和 AI 比谁先猜出来」 |
| 2:00 | 第一轮:出题人抽题(屏幕只给出题人看不现实——灯盘本身对所有人可见,所以改成「AI 偷偷出题,画的人按住屏幕上的题目」,见 4.7 开放问题) |
| 5:00 | 大家喊答案,按「揭晓」让 AI 报它的猜测。**AI 猜错的时候气氛最好**(假设) |
| 10:00 | 记分牌:人类 vs AI。风险:电脑和灯盘分两处,要有一个人当「操作员」 |

> 这三类人的共性假设:**他们不想学规则,想马上有反应;他们会被「别人/AI 的反应」逗笑,而不是被「自己创作的作品」打动。** 这条假设决定了我们更倾向「互动游戏」而不是「创作工具」。要用 6.1 的测试验证。

## 2. 产品定位与一句话卖点

**定位:** 给整个家庭的「会发光的像素游戏机」——用手边这块 8x8 灯盘,和一个看得懂你画的东西、会接话的 AI 玩。

**一句话卖点(候选):**
- 「你在灯上画,AI 来猜,猜错了更好笑。」(推荐)
- 备选:「8x8 的画,AI 也敢猜。」

**为什么小白会想玩:**
1. 不用懂任何东西:按亮的键=有反应,零规则。
2. 灯盘本来就是 64 个像素点,「在上面画画」是它形状里自带的玩法,不需要先解释。
3. 反馈来自「一个会犯错、会接话的对手」,每次结果不同,而不是同一个固定动画。

**为什么玩完会想再玩(假设,待 6.1 验证):** 每次的题目不同;AI 猜错的笑点不可预测;孩子想「难倒 AI」(有对抗目标);画册有积累;每日一题有日更理由。

## 3. 候选玩法(5 个,覆盖 5 种不同类型)

评估原则:先问「AI 在哪里真正起作用?没有 AI 差在哪?」。**灯盘特性约束**:无力度、无声音、无屏幕、8x8 分辨率。

### 3.1 候选 1:灯灯猜猜(像素你画我猜)——互动游戏类
- **玩法:** 灯盘 = 8x8 画布。右侧 8 键 = 调色板,点格子上色。画完按完成,AI 猜「这是什么」。反向模式:AI 出题让人猜它画的,或「AI 偷偷出题,人画,人和 AI 抢答」。
- **AI 真正起作用的地方:** (a) **开放词汇识别**:人随便画什么,AI 都能给出猜测,不用预置模板;(b) **接话**:对人画的东西和自己猜的错误即兴评论;(c) **出题**:按年龄/场景生成无限题目。
- **没有 AI 差在哪:** 只剩一个涂色板;识别只能靠预置模板匹配,词表有限、人一画偏就判不出;没有对手感。
- **难度:** 中。灯控简单;难点是 AI 对 8x8 彩色点阵的识别质量 `[待验证,第一天先做离线摸底]`。
- **风险:** (1) 8x8 信息量极小,LLM 命中率可能低 → 缓解:命题模式下让 AI 在「6 选 1 候选词」里选,自由模式只要求「像什么」,并把「猜错」设计成笑点而非失败;(2) 孩子/家长觉得「AI 猜得不准=产品坏了」;(3) 独自玩复玩动机弱;(4) 画的数据上云(只是 64 格颜色,无摄像头/麦克风,仍须告知)。

### 3.2 候选 2:说一句话,变出一台乐器/灯景——创作工具类
- **玩法:** 小白说/打一句话(「下雨的夜晚猫咖啡馆」),LLM 把它翻译成一套参数:调色板、音阶、音色、背景动画、触碰涟漪样式。随后灯盘变成那个氛围,按键就发声发光。
- **AI 作用:** 把自然语言**映射到受控参数集**(JSON schema 约束),是真实的语义理解,同时规避让 LLM 直接控制 MIDI 的不可靠。
- **没有 AI 差在哪:** 退化成「选 8 个预设主题」,每个人听到的都是同一套。
- **难度:** 中偏高。音频实时性、音色库、音阶设计都要打磨。
- **风险:** (1) **按键无力度** [MK2手册],表现力上限低;(2) Windows 下 Python 播放声音延迟 `[待验证]`,按下到发声超过约 50~80ms 就会觉得「不跟手」(这是行业经验值,`[未核实]`);(3) 新鲜感衰减快,5 分钟后只剩「按键发声」;(4) 与「AI 作曲」类产品同质,易被当成贴牌。

### 3.3 候选 3:AI 地下城(8x8 迷宫冒险)——叙事冒险类
- **玩法:** 灯盘是一张小地图,顶排四个方向键(▲▼◀▶)移动,亮点是自己,不同色是怪物/宝箱/门;LLM 当「地下城主」,按剧情动态生成每一层地图和遭遇,并用语音/屏幕讲述。
- **AI 作用:** 生成关卡与剧情、对玩家任意自由输入(说话)作出情节反应,这是传统脚本做不到的开放性。
- **没有 AI 差在哪:** 只剩固定的几十个关卡,可重玩性很低。
- **难度:** 高。需要稳定的「JSON 地图 + 规则校验」,否则会生成出走不通的图。
- **风险:** (1) 依赖大量阅读/听,低龄孩子不适合;(2) 每回合一次 LLM 调用,延迟/成本累积;(3) 内容安全(孩子场景必须审核);(4) 与硬件的契合度一般,用键盘手柄也能玩。

### 3.4 候选 4:灯语 Simon(记忆/节奏闯关)——街机类
- **玩法:** 灯盘按序亮格子,人复现序列,越来越长。AI 教练按你的表现调整难度、编序列、给鼓励。
- **AI 作用:** **较弱**——自适应难度用简单算法就够,LLM 只是「教练台词」。
- **没有 AI 差在哪:** 几乎没差别,只少一些台词。这是**典型的「贴牌 AI」风险项**,列出作为对照。
- **难度:** 低。**风险:** 被评价为「老游戏换皮」;适合作为热身小游戏,不适合当主打。
- 参考:Simon 为 Milton Bradley 1978 年电子玩具 `[未核实]`。

### 3.5 候选 5:黑白棋对战,带性格的对手——棋类
- **玩法:** 8x8 灯盘本身就是黑白棋(Reversi/Othello)棋盘,红绿代表双方。可选对手性格:调皮、严肃、会讲解的老师。
- **AI 作用:** 落子由**传统搜索引擎**算(这点不能说成 LLM);LLM 负责**性格化评论与教学提示**(「你这步让我拿到了角」)。
- **没有 AI 差在哪:** 没有棋力会很无聊,没有 LLM 就只是冷冰冰的棋类程序。
- **难度:** 低~中(规则成熟)。**风险:** 对小白有规则门槛(要学翻棋);「AI」价值在评论而非决策,偏弱;要实现正确且强度可调的引擎。

### 3.6 比较表(1~5 分,5 最好;**主观判断,不是实测**)

| 维度 | 1 灯灯猜猜 | 2 变乐器 | 3 地下城 | 4 灯语 Simon | 5 黑白棋 |
|---|---|---|---|---|---|
| 零规则上手 | 5 | 5 | 2 | 4 | 2 |
| AI 不可替代性 | 4(开放识别+接话) | 3 | 5 | 1 | 2 |
| 与 8x8 灯盘契合 | 5(64 格=画布) | 3 | 3 | 4 | 4 |
| 多人/家庭 | 5 | 3 | 2 | 3 | 3(2 人) |
| 无声无屏时的可玩性 | 4 | 2(需声音) | 2(需读/听) | 4 | 4 |
| 1~2 周可做出 | 4 | 3 | 1 | 5 | 4 |
| 断网可降级 | 3(可退为互猜) | 4(预设主题) | 1 | 5 | 5 |

### 3.7 MVP 选择:候选 1「灯灯猜猜」

理由(按用户价值):
1. **小白零门槛**:没有音乐/规则/编程要求,孩子能玩、聚会能玩;不依赖声音(设备本身无声)。
2. **灯盘形状天生适配**:8x8 RGB 灯 = 8x8 像素画布。其他候选里灯盘只是「按钮板」。
3. **AI 不是贴牌**:开放词汇识别 + 即兴接话 + 无限出题,拿掉 AI 玩法就塌了(对比候选 4/5)。
4. **失败也可玩**:AI 猜错本身是笑点;断网可降级为「家人互猜」(仍可玩,不是黑屏)。
5. **便宜**:一轮一次文本调用(64 格 ≈ 几百 token,`[估算]`),不需要图像/语音识别。

**此选择有一个必须尽早证伪的前提:LLM 能不能大致猜出 8x8 点阵。** 所以第 1 天做离线摸底(见 5.4),命中率太低就改成「命题+候选词」模式,仍可做。

不选候选 2 的原因:无力度 + 声音延迟两个硬风险叠加,且最容易变成「AI 作曲」同质品;可作为第二期的「胜利音效/背景氛围」。

## 4. MVP 详细设计:灯灯猜猜

### 4.1 设计原则
- **亮的才能按。** 不亮的键=没用。小白不需要看说明。
- **灯盘管「手感」,电脑管「话」。** 灯盘只做反馈(颜色/呼吸/闪烁),所有文字和语音在电脑屏幕上(灯盘只支持 ASCII 滚动文字 [MK2手册])。
- **一次只教一个动作。** 开场用「呼吸提示」一步步引导,不弹教程。
- **AI 只陈述观测,不替人下结论。** 与产品红线一致:AI 说「我看到……像……」,不评价「画得不好」,不推测动机。

### 4.2 按键映射(Session 布局,通道 1;启动时发 SysEx 22h 00 强制)

| 区域 | 作用 | 灯反馈 |
|---|---|---|
| 主盘 64 键 | 画布像素。按一下涂上当前颜色;再按同色格子=擦掉 | 即时变色(本地,不等 AI) |
| 右侧 8 键(note 19…89 `[待验证]`) | 调色板:8 色 | 8 色常亮;当前色呼吸 |
| 顶排 CC 104 | 撤销 | 有可撤销时亮白,否则灭 |
| 顶排 CC 105 | 清空(需连按两次,第一次闪烁提示) | 灭/亮橙 |
| 顶排 CC 106 | 换题 / 跳过 | 有题目时亮 |
| 顶排 CC 107 | 提示(AI 说一句描述,不泄露答案)(第二期) | MVP 不亮 |
| 顶排 CC 108 | **完成!让 AI 猜**(最重要) | 画满 ≥3 格后绿色呼吸,按下后常亮 |
| 顶排 CC 109 | 切模式(自由画/命题/家庭对战) | MVP 可只做 2 个 |
| 顶排 CC 110 | 画册 | 有存画时亮 |
| 顶排 CC 111 | 声音开/关 | 常亮 |

说明:顶排上的字样(▲▼◀▶/Session/User1/User2/Mixer)是印刷,我们的映射与印刷无关,**按 CC 号处理**。**不使用 Session/User 键的出厂切换功能**:每次启动强制 Session 布局;如果上机发现按这些键会自己切布局,需要在软件里收到后立刻再发一次布局 SysEx `[待验证]`。

画布颜色:用 RGB SysEx 渲染(每色 0~63),保存一份本地 64 格的颜色表(设备不可读回)。**注意:闪烁/呼吸只能用调色板号**,不是 RGB;所以 8 个调色板颜色要选「在调色板里有对应号」的颜色,上机时需对色(见 6.4)。手册示例里出现过的色号:5=红、21=绿、45=蓝、81=紫、53=粉、13=黄、9=橙(来自示例,未经上机核对)。

### 4.3 开场 30 秒上手(目标:30 秒内完成第一次「AI 回应我」)

| 秒 | 灯盘 | 电脑屏幕/声音 |
|---|---|---|
| 0~3 | 彩虹波纹从一角扫过全盘(本地预渲染帧) | 大字:「灯灯猜猜」+ 一个小动画 |
| 3~8 | 只有中间一格在呼吸闪 | 大字:「按一下发光的键」(同步朗读) |
| 8~15 | 按下→变色+「叮」,右侧调色板亮起,下一个呼吸点转移到某一格 | 「很好!换个颜色再按一格」 |
| 15~25 | 玩家自由涂;画 ≥3 格后,顶排 108(完成)转绿色呼吸 | 「画好了就按绿色的键」 |
| 25~30 | 按完成→扫描动画(整盘亮线从下往上扫,本地播放,同时后台调 AI) | 「我来看看……」→ 「我猜是……」 |

**如果 15 秒内没人按任何键:** 呼吸点加快,屏幕大字重复一次;45 秒仍没有 → 自动进入「演示」:灯盘自己画一个笑脸,让人看到「这东西能画」。**绝不弹出长文本说明。**

### 4.4 一轮游戏流程(状态机在本地,不依赖 AI)

```
ONBOARD → CHOOSE_MODE → DRAWING →(按完成)→ THINKING →(AI回话/超时)→ REVEAL → (下一题 / 存画册 / 结束)
```
- **DRAWING**:全部在本地。按键→LED 目标 ≤ 50ms(拟定验收线)。
- **THINKING**:灯盘本地循环扫描动画;屏幕显示「我想想……」。**最长等待 6 秒**,超时进降级回复(见 4.6)。
- **REVEAL**:屏幕给出 AI 猜测(首选 + 备选 2 个),灯盘做出反馈:AI 猜对=全盘绿色闪一下;猜错=不用红色,用柔和的黄色呼吸(避免对孩子的负面信号)。
- **命题模式**:题目从预置+LLM 扩展词库抽取;AI 只在「6 个候选词(含答案)」里选并说理由;答对加分。
- **家庭对战模式**:一人画,其他人和 AI 抢答,按「揭晓」让 AI 报答案,记分牌累计(人 vs AI)。这是画像 C 的主场景。

### 4.5 出错怎么办(用户视角)

| 情况 | 用户看到什么 | 备注 |
|---|---|---|
| 按了没亮的键 | 该键瞬间微弱白光一闪(表示「收到了,没用」),不报错 | 不用红色 |
| 灯盘未连/被占用 | 屏幕:「没找到灯盘,请插好 USB,再关闭其他音乐软件」 | Windows MIDI 端口通常独占;检测靠每秒枚举端口 `[待验证]` |
| 中途拔线 | 屏幕提示 + 保留当前画布,重插后一键恢复(灯需整盘重发) | 设备无状态读回,必须重绘 |
| AI 超时/无网 | 见 4.6 | 对用户诚实 |
| 退出程序 | 发全灭 SysEx(0Eh 0)并恢复 Session 布局 | 不能留一盘亮着的灯 |

### 4.6 AI 的话:文案红线(与产品原则一致)
- 只描述**画面上看到的东西**:「我看到黄色在中间,周围有一圈小点,像太阳。」
- 猜错时责任在 AI:「这次我没猜对,能告诉我答案吗?」(用户告诉后写入本地「个人词典」,下次可优先匹配——这是一个很小的「越用越准」,**但 MVP 里仅做存储,不承诺识别率提升**)。
- 不评价画画水平,不说「画得很差/很棒」这类比较性结论,不推测孩子的动机或状态。
- 无网/AI 失败时**如实说**:「AI 现在没连上,我们用互猜模式吧」,不得假装 AI 在猜。

### 4.7 LLM 调用时机与延迟/成本控制

| 事件 | 必须本地即时 | 可异步调 LLM | 目标 |
|---|---|---|---|
| 按键→灯变化 | ✔ | | ≤50ms,(拟定) |
| 按键→音效 | ✔(预载入音效文件) | | 声音延迟 `[待验证]` |
| 调色板/撤销/清空/完成 | ✔ | | 同上 |
| 扫描等待动画 | ✔(本地循环) | | 立即 |
| 猜测 | | ✔ 1 次/轮 | p50≤2.5s,硬超时 6s(拟定) |
| 对战评论 | | ✔ 合并进猜测调用(一次返回猜测+评论+备选) | 不额外调用 |
| 出题 | | ✔ 启动时/每日批量预生成,存本地题包 | 游戏中不即时生成 |
| 个人词典 | 本地 | | |

成本控制:
- 每轮 **1 次**文本调用;输入是 64 格颜色文本(8 行×8 字母,约几百 token,`[估算]`),输出要求严格 JSON(猜测×3、一句评论、置信度)。
- 题包与固定台词在本地预置,首次启动、每日一次批量扩充。
- 对同一个画面做哈希缓存(比如「撤销后重画一致」不重复调用)。
- 每设备每日调用量设上限(默认值待用户定,见开放问题)。
- **用 pydantic 校验 LLM 的 JSON**,不合格重试 1 次,仍失败走降级。LLM 绝不直接控制 MIDI。

### 4.8 离线/无网降级(诚实分级)

| 级别 | 条件 | 能玩什么 | 对用户的话 |
|---|---|---|---|
| L0 | 正常 | 全部 | |
| L1 | 超时/偶发失败 | 本轮改用本地模板匹配(预置 ~60 题的参考点阵,相似度粗匹配,仅命题模式) | 「我想不出来,让我看看题库里最像的……」 |
| L2 | 完全无网 | 家人互猜(屏幕出题+计时+计分,灯盘只作画布) | 「AI 休息中,我们自己猜」 |
| L3 | 灯盘未连 | 提示排查,不给假界面 | |

可选:本地小模型 `[待验证]`,不纳入 MVP。

### 4.9 隐私与安全(产品属性)
- 上云的只有 8x8 颜色矩阵(无摄像头、麦克风、人像)。首次启动屏幕明说「AI 会看到你画的 8x8 小图」,默认云端,可一键切离线。
- 画册、个人词典**只存本机**,提供「一键清空」(诚实语义:仅删除本机文件,**不承诺已发给 LLM 供应商的数据被删除**,以供应商条款为准 `[待验证]`)。
- 孩子场景:题库预审(白名单);LLM 生成的题目/评论过一层关键词与长度过滤;不存姓名。
- 是否面向 13 岁以下儿童、监护人同意如何做:列入开放问题。

## 5. 技术方案草图(一个人 1~2 周)

### 5.1 模块划分

```
app/
  midi_io.py     # mido + python-rtmidi:开/关端口、输入队列、断线检测
  launchpad.py   # 设备抽象:LED 帧缓冲、脏格合并、RGB SysEx 批量发送、布局初始化、清理
  sim.py         # 软件模拟盘(Tk 画 8x8),无设备也能开发和自动化测试
  game.py        # 本地状态机、计分、模式、计时(不含 AI)
  ai.py          # LLM 客户端:提示词、JSON schema、超时、重试、缓存、降级
  content.py     # 题包(JSON)、固定台词、个人词典
  host_ui.py     # 电脑屏幕:大字、AI 台词、记分牌、画册(Tkinter)
  audio.py       # 本地音效 + 可选 TTS
  config.py      # 模式、每日上限、联网开关
tests/           # 针对 sim 的状态机测试;针对 ai 的 mock 测试
```

### 5.2 MIDI 层
- 库:`mido` + `python-rtmidi`(任务已指定;均为 PyPI 公开库 `[未核实版本兼容性]`)。
- 端口名用子串匹配 `Launchpad MK2`(README 记录了 Windows 下带前缀的形式 `IN 0 / OUT 1`),不写死。
- **发送策略:** 画布更新用一条 SysEx 0Bh 批量带多格(手册:最多重复 80 次)[MK2手册·RGB Mode];单次按键只发一格。动画限帧 ≤30fps,并做「脏格合并」。
- **速率:** MK2 手册**没有写**吞吐上限;README 的「约 400 条/秒」来自**原版**协议手册,不能直接套用。需上机压测 `[待验证]`:连续发 1000 条 SysEx,看是否丢/乱。
- **输入:** 回调线程只往队列放事件,主循环消费,避免回调里做重活。
- **启动与退出清理:** 启动:发设备询问(F0 7E 7F 06 01 F7)确认型号与固件、切 Session 布局、全灭;退出:全灭。

### 5.3 AI 层与声音/视觉输出
- **AI:** 一个 `OpenAI 兼容 HTTP 接口` 的薄封装(`httpx`),这样可换云端或本地推理服务;具体用哪家见开放问题。提示词只给 8x8 字母矩阵+色表,要求输出 JSON;`pydantic` 校验。
- **视觉:** 灯盘=手感反馈;屏幕=大字+记分牌(Tkinter,零依赖,小白可直接双击运行)。
- **声音:** 设备无声音,走电脑。音效用短 WAV(`pygame.mixer` 或 `sounddevice`,二选一,Windows 延迟 `[待验证]`);朗读用 `pyttsx3`(Windows SAPI5,是否有中文语音 `[待验证]`)或联网 TTS(如 edge-tts `[未核实]`)。MVP 可先只做屏幕大字+几个音效,朗读放第二期。
- **现成库 vs 自写:** 现成 = mido、rtmidi、httpx、pydantic、Tkinter、pygame;自写 = LED 抽象、状态机、提示词、题包。可参考开源 `launchpad.py`(FMMT666,GitHub)的设备抽象方式 `[未核实,是否覆盖 Mini MK2 待验证]`,但本方案只需发 SysEx,自写更简单。

### 5.4 1~2 周拆解

| 天 | 内容 | 需要硬件 |
|---|---|---|
| D1 | **AI 摸底**:手工做 30 个 8x8 简图(太阳/房子/猫/爱心/树…),用 3 种提示词+2 个模型试猜,统计 top-1/top-3 命中率与延迟 | 否 |
| D2-3 | `launchpad.py` + `sim.py` + 状态机;灯盘上机对色、压测速率、确认 RGB 与顶排/右排编号 | 是(需用户当次同意) |
| D4-5 | `ai.py`、`content.py`、`host_ui.py`;开场 30 秒引导 | 部分 |
| D6-7 | 音效、记分、画册;降级路径 | 否 |
| D8-10 | 找 5~8 个真人小白试玩,改 | 是 |

**D1 的闸门(拟定):** 命题模式(6 选 1)top-1 命中率 ≥ 60%,自由模式 top-3 命中率 ≥ 40% 才按本方案做;不满足就把自由模式降级为「AI 说『像什么』+ 笑点」,并在文案里不承诺「猜对」。这些数字是起始假设,不是依据。

## 6. 验收与实测

### 6.1 真人小白测试(拟定方案)

- **人数:** 每类画像 5 人,共 ~15 人(5 人/类的做法源自可用性测试经验法则,Nielsen 的文章 `[未核实]`)。这个量只能发现问题,不能做统计推断。
- **招募:** 没用过 Launchpad、不会编程、不玩 DAW。孩子测试需要监护人同意,录像需监护人同意,不同意则只记录笔记。
- **流程:** 设备已接好(我们预装,见 6.4)→ 不做任何口头讲解,只说「随便玩,想停就停」→ 出声思考 → 10 分钟 → 离开桌子 2 分钟(设备保持开机)观察是否自己回来玩 → 问卷+访谈。
- **记录:** 屏幕录像 + 桌面摄像头(经同意);程序日志(按键时间、AI 调用时延、降级触发)。

### 6.2 指标(阈值均为**拟定验收线**,待首轮数据修正)

| 指标 | 定义 | 拟定验收线 |
|---|---|---|
| 首次点亮到第一次按键 | 灯盘亮 → 第一次有效按键 | 中位 ≤ 15 秒 |
| 首次完整一轮 | 灯盘亮 → 首次看到 AI 回应 | 中位 ≤ 60 秒;**无人干预完成率 ≥ 80%** |
| 误按/困惑 | 按无效键次数、「这个键干嘛」问句 | 前 60 秒 ≤ 3 次/人 |
| 笑点 | 观察者标记:大笑/惊讶次数/10 分钟 | ≥ 3 次(参考,待比较) |
| 复玩意愿(行为) | 空窗 2 分钟后主动再玩 | ≥ 60% 的人 |
| 复玩意愿(自述) | 「明天/下周还想玩吗」1~5 分 | 中位 ≥ 4,**以行为为准** |
| 可用性 | SUS 问卷(Brooke 1996 `[未核实]`) | ≥ 68(通用参考线) |
| 技术-按键延迟 | 主机收到按键到发出 LED 的时间(日志) | p95 ≤ 50ms |
| 技术-AI | 响应 p50/p95、降级触发率、猜测 top-3 命中率 | p50 ≤ 2.5s,降级 ≤ 10% |
| 家长安心 | 家长是否问「这画会传到哪」;能否说清「只有 8x8 小图上云」 | 能说清 ≥ 80% |

### 6.3 判定
- **继续做:** 无人干预完成率达标 + 空窗回玩达标,AI 笑点自述高于 3 次。
- **改方向:** 空窗回玩 <30%、或 AI 命中率让用户觉得「它是坏的」→ 转候选 5/2,或把 AI 降为出题人。
- **一票否决:** 孩子出现受挫表现(哭/放弃)且与 AI 评论有关。

### 6.4 已知限制(要对用户诚实)

1. **设备无屏、无声**:所有中文说明、AI 台词、声音必须经电脑。小白实际上要「盯着两处」——灯盘和屏幕。缓解:屏幕只显示一句大字。
2. **8x8 分辨率**:画面信息极少,AI 猜图天然不准,必须把「猜错」设计成可接受/好笑。
3. **按键无力度**:不能做强弱表达 [MK2手册]。
4. **LED 无法读回**:状态必须软件保存;拔插后要整盘重绘。
5. **闪烁/呼吸用调色板号,画布用 RGB**:两套颜色体系需对色。
6. **MIDI 速率未知(MK2)**:README 的 400 条/秒是原版协议数据 `[待验证]`。
7. **滚动文字仅 ASCII**:不能直接显示中文。
8. **Windows MIDI 端口独占**:同一时间只有一个软件能开,安装了 DAW 的用户可能冲突 `[待验证]`。
9. **本机键帽缺角**:几颗键帽有缺角 [README],上机要逐格测按压是否灵敏。
10. **安装门槛**:原型靠我们预装 Python 环境和 Novation 驱动(README 记录已装 2.30.0.84,装后 MIDI 端口行为仍 `[待验证]`),**「小白自己装」没有被验证**,不能把「首次点亮到玩上手」时间算上安装;面向真实小白前要做打包(如 PyInstaller `[未核实]`,注意杀软误报)。
11. **README 中仍有未验证项:** 本机是否确为 Mini MK2 协议兼容、是否点得出 RGB。D2 上机第一件事就是验证。
