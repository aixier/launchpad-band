# 跟打模式(rhythm highway)设计

日期:2026-10-26。实现位置:`product/desktop-prototype-v3/`(双击 `index.html`,顶栏「跟打」)。
文件:`highway.js`(判定/评分/锁定/盘面灯,纯逻辑)、`hwview.js`(画面)、`charts.js`(内置谱面)、`tools/`(自检,见第 9 节)。

## 0. 一页结论

- **产品意义**:最大的成就感 = 听到好听的电音,能在 Launchpad 上快速复刻,并亲手控制节奏。跟打模式把这件事做成可玩的最小闭环:**灯光告诉你按哪一格 → 光条告诉你几时按、按多久 → 你打出一层,它就自己响起来 → 一层层叠成一首歌**。
- **第一问题**(用户补充):键盘类游戏的琴键是一维的,Launchpad 是 8x8,怎么让小白不数格子就知道"按哪里"。结论:**默认「追光落点」**——盘面画成透视格阵,对应列的那盏摇头灯扫向目标格,光斑落在哪格就按哪格,光条沿所在列下坠、落进光斑。理由与比较见第 1 节(含可读性指标)。用户已选定这一方案。
- **灯光语言**:新增「跟打例外条款」(第 5 节,已写入 README 与 launchpad-ux skill):目标键进入判定前窗口时亮**青绿常亮**(不闪);瀑布/追光/光柱/浮字一律不用青绿;跟打期间盘面上没有任何闪烁引导。检查脚本已扩展(第 9 节)。
- **验证**:判定/评分/锁定逻辑 Node 自检全过;无头 Chrome(file://)整流程自检全过(独显、集成显卡、软件渲染三种),控制台错误 0;灯光语言检查 A~G 全过。帧耗时见第 8 节。
- **没做的**(第 11 节):真人试玩、真机(Launchpad)联调、MIDI/音频导入、谱面编辑器、重打本段、变速曲。
- **需要用户拍板的 2 个问题**(第 11 节)。

## 1. 第一问题:怎么让小白知道"按哪里"

### 1.1 问题本质

键盘类游戏(Guitar Hero、Beatmania、Synthesia)里,"按哪里"= 哪一**轨**,光条的横向位置就是答案;一维。Launchpad 是 8x8:一个光条要同时回答**哪一列、哪一行**。若只画 8 条轨,玩家看到光条后还得在这一列的 8 个格里自己找行——这就是"数格子"。三个事实约束了设计:

1. 设备**没有力度、灯不能回读**;玩家手在设备上,眼睛在屏幕上。眼睛一次只能盯一个地方。
2. 小白**没有肌肉记忆**,不能靠"记住谱"。
3. 灯光语言:青绿只给"该按的键"。

### 1.2 候选方案与变体(全部做了比较;可在开始卡片「提示方式」里切换)

| 方案 | 一句话原理 | 直观性 | 代价/风险 | 状态 |

### 1.4 推荐与理由(追光落点)

- **推荐 = 追光落点,辅以设备预备灯与行=声部**。注意力集中在**一个区域**:屏幕下方的格阵。提示、目标、光条、反馈(命中绽放/浮字)全都在这块区域里,不需要在两处之间来回看。
- 玩家只需要学会一件事:**屏幕格阵 ↔ 设备**是同一个朝向、同一个比例(第 1 行最近、最底),这是一次性的映射,而不是每个音都要翻译的映射。
- 设备灯(B)是**余光确认**,不是主要的看点:想不看屏幕、只看设备的人也能玩;想看屏幕的人则不会被迫低头。
- 为什么不选光柱:64 根常态存在,即便压到 7% 白,也是整块区域持续的"毛刺",和舞台上的雾/光束抢画面;追光只在需要时出现 1~3 个光斑,常态是干净的格阵。为什么不选经典:眼动距离与歧义最大,而且把"指挥舞台"的隐喻拆成了两件事。
- 风险 [待验证,需要真人]:看屏幕盲按设备,位置准确度如何;第一次玩时"透视格阵 ↔ 设备"的映射是否一眼能懂。

### 1.5 同时多个光条(和弦)不拥挤

1. **追光分配**(`highway.js: assignLamps`,全曲预先算好,没有运行时状态):每个要打的音配一盏灯,优先用它**所在列**的那盏(盘面第 c 列 ↔ 中排桁架第 c 盏);同一时间已被占用,就借**后排桁架**的灯(离该列最近的优先),再借地面灯。所以同时出现 2~3 个光条也是 2~3 个不同的光斑、不同的灯。
2. **光条很窄**(约格宽 34%),同一列不同行的光条会在屏幕上重叠,但**落点不同**;歧义由光斑解决,不靠光条。
3. **颜色 = 声部**:同时出现的音若属于不同声部,颜色不同;旋律按音名上色。
4. **谱面作者规则**(第 6 节):同一时刻同一声部最多一个音;全曲同时最多 2 个;同一键相邻两个音至少空 0.25 拍(手指要能抬起来再按)。演示谱面里同一时刻 0 个同时光条,最短相邻间隔 0.25 拍。
5. **预备窗只有 0.4 s**:盘面上同时亮着的青绿最多 3 个(整首实测,见第 9 节)。

## 2. 交互与视觉设计

### 2.1 屏幕

- 画布铺在舞台区之上,**舞台仍是主画面**(WebGL 或 2D 降级),格阵只占下方中央约 44% 宽、36% 高;盘面镜像仍在左下角(跟打时缩小到 200~250 px,它是余光确认,主角是格阵;窄屏 < 760 px 时隐藏)。
- 顶部中间:四个声部条(鼓/贝斯/和弦/旋律,当前层高亮,打好的层带 ✓);右上:连击、准确率、亮灯提示状态;右下:退出。其余界面全部退场。
- 色彩纪律:界面无彩色(暖黑 + 暖纸白),颜色只属于音乐。

### 2.2 一首歌的流程

进入 → 开始卡片(难度 / 行数 / 亮灯提示 / 提示方式 / 节拍声 / 校准 / 开始)→ 倒数 4 拍 → 四段(每段 6 小节 = 12 s):**先打鼓 → 加上贝斯 → 加上和弦 → 加上旋律** → 结果卡片(星级、按下/按住分开、最高连击、叠上几层)→ 再来一次 / 改设置 / 退出。空格暂停,Esc 退出,Enter 开始。

### 2.3 追光的手感(默认方案的核心)

| 要素 | 设定 | 为什么 |
|---|---|---|
| 预判时间 | 光斑在落地前 **0.38 s** 到位;之前扫动最长 0.7 s | 0.38 s ≈ 视觉反应 + 手移动的预算;太早会让玩家等,太晚来不及 |
| 缓动 | 起点 → 目标用 smootherstep(五次缓动,两端速度为 0),不是弹簧 | 弹簧有回弹,"到位"的时刻不确定;时间参数化的缓动保证**到位时刻与谱面严格同步** |
| 扫动期亮度 | 20% → 逐步升高;到位后升到 100% | 扫动像"灯在找",到位像"灯锁定" |
| 光斑形状 | 地面圆(透视压成椭圆),**中心实、边缘 14% 渐隐**,外缘一圈细亮线;尺寸 ≈ 一个格子 | 边缘清晰才读得出是哪一格;圈内暖色随声部 |
| 接近圈 | 落地前 0.6 s 起,一圈暖白细线从 2.25 倍向内收缩到光斑边缘,**碰到光斑 = 现在按**(类似 osu! approach circle) | 光条给"长度",接近圈给"精确时刻";两者不冲突 |
| 光条 | 沿所在列从上空下坠,落地前 1.4 s 出现,头部有亮帽;落点 = 光斑中心 | 长度 = 按住时长;**落进光斑的瞬间 = 应按下的时刻** |
| 按住期间 | 追光**保持**,光斑边缘外圈随剩余时间收尾(弧线走完 = 该松开),光条被"压"在格子上、尾部下降 | "到尾部松开"变成"看圈走完" |
| 松开 | 追光 0.3 s 内熄灭;浮字「松得准 / 松得还行 / 松早了 / 拖长了」 | |
| 命中 | 格子上扩散一圈光环 + 一缕向上的光柱,**同一时刻该列的摇头灯亮起、喷火花**(舞台联动),浮字「完美 / 不错 早·晚」 | 命中 = 你的手在指挥舞台 |
| 漏拍 | 光斑变灰熄灭,浮字「漏拍」,连击清零,舞台灯收敛 | 不惩罚,只是"灯暗一下" |
| 青绿预备 | 目标格在落地前 **0.4 s** 描边青绿(屏幕格阵)+ 盘面该键亮青绿,**常亮不闪**,命中/漏掉即灭 | 灯光语言例外条款(第 5 节) |

真实的摇头灯也同步:每帧把"第 i 盏灯正在追光到第 r 行、什么颜色、多亮"告诉灯光导演(`dir.spot`),所以舞台里那盏灯的光束、雾里的光锥、灯口光晕都跟着亮起并按行抬/压;屏幕格阵上的光斑 + 光锥是同一件事在地面上的落点。**局限**:真 3D 光束的落点与 2D 光斑不是同一几何(格阵是 2D 叠加层,不在 3D 场景里),因此 3D 光束只表达"这盏灯在追光",精确落点由 2D 光斑给出;把格阵做进 3D 地面需要专门机位 [待验证,见第 11 节]。

### 2.4 自适应与减少动效

- 画布 2D 绘制,每帧 0.3~0.5 ms(第 8 节),几乎不增加舞台负担;舞台沿用自适应画质(动态分辨率 → 降档)。
- `prefers-reduced-motion` / 设置里的「减少动效」:去掉命中向上光柱;舞台去掉镜头运动与频闪(沿用 v3)。追光扫动、光条下坠属于功能性动画,保留。
- 键盘:A S D F J K L ; = 8 列(不用管行);其余键仍按原四排键位对应具体的格;空格暂停;Esc 退出。

## 3. 判定与评分

按下与按住**分开计**,再合成一个准确率。

| 项 | 轻松(默认) | 严格 |
|---|---|---|
| 按下:完美 | ±85 ms | ±45 ms |
| 按下:不错 | ±170 ms | ±100 ms |
| 窗口之外 | 同一个音的窗口外按下 = 该音漏拍(提示「早了/晚了」);没有任何光条的杂键 = 静默、不惩罚 | 同左 |
| 按住:松得准 | 尾部 ±170 ms | ±90 ms |
| 按住:松得还行 | ±340 ms | ±200 ms |
| 早松 / 拖长 | 比「还行」窗口更早/更晚 | 同左;晚于「还行」窗口仍按着,系统自动结束这个音并记「拖长」 |
| 叠上一层的门槛 | 本段准确率 ≥ 50% | ≥ 70% |
| 星级(整首准确率) | ★ ≥ 50% / ★★ ≥ 72% / ★★★ ≥ 88% | ≥ 60% / 80% / 93% |

- 光条分两类:**短点**(时值 < 1 拍,只判按下)和**按住**(≥ 1 拍,判按下 + 判松开)。
- 评分:`按下准确率 = (完美×1 + 不错×0.7) / 总数`;`按住准确率 = (松得准×1 + 松得还行×0.7 + 早松/拖长×0.3 [按下命中的] ) / 按住总数`;`准确率 = 0.7×按下 + 0.3×按住`(没有按住类光条时只看按下)。
- **连击**只由按下推动;漏拍清零。按住松早/拖长不断连击(只扣按住准确率)——"按下节奏"与"按住时长"是两种能力,不混在一起惩罚。
- **没有力度感应**:所以不做力度评分;灯光强度由"命中质量 + 连击"驱动(见第 7 节)。
- **延迟校准**:一切以 WebAudio 时钟(`ctx.currentTime`)为准;画面与判定用的是"耳朵听到的歌曲时间" = 歌曲时间 − 输出延迟;再扣掉用户校准值(人 + 设备 + 屏幕的整体延迟)。校准步骤:点「校准延迟」→ 9 下节拍(100 BPM)→ 跟着按任意键 → 丢掉前 2 下,去掉最大最小值取平均 → 保存(限制在 −200 ~ +300 ms)。自检:模拟玩家比节拍晚 70 ms,校准得到 +71 ms;偏晚 90 ms 的玩家在严格档下未校准打不上鼓(准确率 49%),校准后能叠上(100%)。
- **亮灯提示的过渡**:「自动淡出」= 一直亮 → 一段打到 ≥ 85% 后,只亮每小节第一个 → 再一段 ≥ 85% 后,不亮灯(看屏幕打)。这是"从跟着青绿灯走过渡到看瀑布打"的路径;也可手动选「一直亮 / 不亮」。

## 4. 一层层叠加:成就感从哪来

- **每一层只在自己那一段由玩家亲手打**:第 1 段只有鼓,第 2 段加贝斯(鼓已经在响),第 3 段加和弦,第 4 段加旋律(前三层都在响)。
- **打出每一层时,对应声部才响起**:玩家按对了,那个音当场发声(鼓/贝斯/和弦/旋律各用自己的合成音色);按错、漏拍、没打到 = 静默(只有一点点节拍声当"暗淡背景",可关)。
- **打得够好(轻松 ≥ 50%、严格 ≥ 70%)这一层就被"锁定"**:之后的各段由乐队**按谱精确接力**回放;没打好则这一层静默,后面少一层——你听得出缺了什么。
- 取舍:接力回放的是**谱面**,不是"录下你的手"。理由:你的手有抖动,录下来回放会越来越松垮、不好听;按谱回放让"我复刻出来了"的结果始终是好听的。代价:接力的声音不完全是你打的节奏。将来可做可选项"用你的手感做轻微 swing" [未做]。
- 完成时:整盘暖彩虹 + 金星,舞台撒金色彩带 + 冲击波,琶音(沿用奖励效果,与引导的青绿闪烁区隔)。
- 自检(无头 Chrome,自动打手 ±30 ms 抖动):鼓只在第 1 段由用户出声(34 次),第 2 段起乐队接力(144 次,从 12.00 s 起);贝斯由用户在第 2 段打出(23 次),第 3 段起接力(从 24.00 s 起);旋律只有用户出声;第 1 段里没有任何贝斯/和弦/旋律的声音;**整层不打贝斯**时,贝斯没被锁定、全曲没有贝斯声,其余三层不受影响。

## 5. 灯光语言修订:跟打例外条款

> 已追加到 `README.md`「灯光语言修订 2026-10-26」与 `.claude/skills/launchpad-ux/SKILL.md`;旧条文在跟打模式之外一字不改。

**条款**

1. **青绿常亮仅限跟打**:跟打期间,光条进入判定前窗口(0.4 s)的目标键亮 `GUIDE(0,63,40)` **常亮,不闪**;命中或漏掉后立刻熄灭(命中后改绽放声部色)。
2. **为什么常亮、不闪**:节奏提示需要"几时按"的精度。1 Hz 硬闪烁的亮相每 0.5 s 才出现一次,与"该按的那一刻"对不上。跟打里**时间由屏幕上的光条/追光/接近圈表达,灯只回答"按哪一格"**——所以灯可以常亮。
3. **为什么不破坏一致性**:(a) 青绿仍然只代表"下一步请按这里",且只给该按的键;(b) 色相 0.40~0.55 仍为引导独占——瀑布、追光、光柱、浮字、格阵、舞台灯、背景、UI 都不含青绿;(c) 跟打期间盘面上**没有任何闪烁的引导**(开场引导链、练习、顶排引导键全部让位),所以不会同时存在"闪的青绿"和"常亮的青绿"两种语言;(d) 离开跟打后,全产品其余引导恢复 1 Hz 同相闪烁。
4. **颜色分工**:光条 = 声部色(鼓 橙 / 贝斯 粉 / 和弦 紫)或音名色(旋律:红橙黄紫粉);判定提示/接近圈 = 暖白;命中反馈 = 声部色;舞台灯 = 声部色/音名色/暖白;金色只属于完成奖励。
5. **盘面其余键**:整盘底色压暗(10/63)以衬托预备青绿;顶排前 4 键 = "叠上几层"的声部指示(暗 = 没叠上,亮 = 已叠上);右列 = 歌曲进度。
6. **舞台**:跟打期间舞台**不再"安静"**,而是被命中驱动(这不是与引导抢眼:舞台只在你命中后回应,无命中时没有自走特效);完成奖励沿用暖彩虹 + 金星 + 琶音。

**检查脚本**(`tools/check_lightlang.js` 新增 G 段,全过):
- G1 4 个声部色 + 477 个音(含两行难度)的光条色不落入引导色相;
- G2 整首 4298 帧(含漏拍、按住、完成):盘面青绿格逐帧等于"预备集合"(该按的键),最多同时 3 个,常亮、从不出现闪烁暗相,其余键/顶排/右列无引导色相;G2b 每个预备灯连续常亮;G2c 完成仪式无引导色相;
- G3 画布录制:三种提示方式 × 378 帧,34157 次颜色设置里,引导色相只有 560 次,**全部是带 `prep` 标记的"该按的格"预备描边**;
- G4 舞台长跑 6000 帧(命中色 = 声部色、追光、漏拍、完成仪式),灯/雾/屏墙/冲击波/粒子每帧审计 0 处;
- G5 命中越准灯越盛(能量 0.12 → 0.85,灯总亮度 ×1.5,受总亮度上限限制);漏拍后 0.3 s 内灯总亮度 −45%,约 2.5 s 恢复。
- 无头 Chrome 里另有渲染像素审计(集成显卡整首 2500 余帧 0 个青绿像素)与"盘面青绿只出现在该按的键、从不出现闪烁暗相"的页内检查。

## 6. 谱面格式 `lp-chart/1`

JSON 可序列化(`charts.js` 用代码生成 notes 只是为了写得短,生成结果是纯数据)。时间单位 = **拍**(四分音符),从第 1 个小节的第 1 拍起算(倒数在它之前)。

```json
{
  "format": "lp-chart/1", "id": "demo-edm-1", "title": "电音小样", "artist": "自合成(本项目)", "license": "自制,可随意使用",
  "bpm": 120, "meter": [4, 4], "key": { "tonic": 60, "mode": "major", "chords": ["Am","F","C","G","F","G"] },
  "countIn": 4, "endBeat": 96,
  "source": { "kind": "handmade" },
  "layers":   [ { "id": "drums", "name": "鼓", "hue": 0.07, "section": 0, "row": 1, "tip": "先打鼓:光落在哪格就按哪格" } ],
  "sections": [ { "id": "s1", "name": "鼓", "layer": "drums", "b0": 0, "b1": 24 } ],
  "notes": [
    { "t": 0,  "d": 0.1,  "layer": "drums",  "pad": 13, "v": { "k": "kick" } },
    { "t": 12, "d": 1,    "layer": "bass",   "pad": 22, "v": { "k": "bass",  "m": 45 } },
    { "t": 24, "d": 2.5,  "layer": "chords", "pad": 32, "v": { "k": "chord", "m": [57, 60, 64] } },
    { "t": 72, "d": 1,    "layer": "melody", "pad": 44, "adv": 52, "v": { "k": "lead", "m": 81 } }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `bpm` / `meter` / `key` | 速度(恒定)、拍号、调性(tonic = MIDI 音高;chords = 每段的和弦走向,仅作展示/和弦色) |
| `layers[]` | 声部;`section` = 它由玩家亲手打的段序号;`row` = 它在盘面上的行带(行 = 声部);`hue` = 声部色相(必须在红橙黄紫粉内,检查脚本会验证) |
| `sections[]` | 段 = 一个声部加入的时间区间(`b0~b1` 拍) |
| `notes[].t / d` | 起点、时值(拍)。`d ≥ 1` 为"按住"类,否则为"短点" |
| `notes[].pad` | 盘面键 = 行×10 + 列(行 1 在最下;Session 布局的 note 号) |
| `notes[].adv` | 可选:进阶「两行」难度下改按的同音键(旋律用:第 4 行的音在第 5 行有同音键) |
| `notes[].v` | 出声方式:`k` ∈ kick/snare/hat/bass/chord/lead;`m` = MIDI 音高(chord 为数组) |
| `source` | 谱面来源,`kind` ∈ `handmade` / `midi-import` / `ai-transcribed` |

玩家要打的音 = 落在自己声部那一段里的音;其余是该声部在后面各段的"接力"音(只在该声部被锁定时才会出声)。

**谱面作者规则**(`tools/check_highway.js` A 段逐条验证):R1 玩家段的最后一个音必须在段尾前 1 拍结束(留出判定与锁定决策的空档);R2 同一声部同一时刻只有一个音;R3 同一键相邻两个音之间至少空 0.25 拍;R4 所有键在 8x8 网格内,入门难度每个声部一行;R5 全曲同时最多 2 个光条;R6 一段的音符数 ≤ 约 40(≈ 3.3 个/秒)。

### 为"AI 从歌曲生成谱面"预留的字段(未实现,只定了结构)

- `source`:`{ "kind": "ai-transcribed", "fileHash": "...", "stems": ["drums","bass","other","vocals"], "tools": [{ "name": "demucs", "version": "..." }, ...], "confidence": 0.0~1.0 }`;音符可带 `c`(置信度)用于难度裁剪时先丢低置信度的音。
- 变速曲:`tempoMap: [{ "beat": 0, "bpm": 128 }, ...]`(节拍→秒的映射);音符仍用拍,换算由 `tempoMap` 完成。节拍追踪的原始输出(每个拍的时间点 `beats: [秒…]`)也存进来,便于回放对齐。
- 难度分级:`notes[].tier`(1/2/3)——同一首歌导出入门/进阶/全盘三套难度,而不是三份谱面。
- 起止时间:AI 转写给出的是**秒**;转换器量化到 1/8 或 1/16 拍并保留原始 `ts/ds`(秒)作为校验。

## 7. 舞台联动与起承转合

| 事件 | 舞台反应 |
|---|---|
| 命中 | 该列那盏摇头灯亮起(声部色)、喷火花、屏墙出现命中光斑;`gain` = 完美 1.0 / 不错 0.78(设备没有力度,用命中质量代替) |
| 追光(落地前) | 对应灯按 `(行-1)/7` 抬/压光束,光色 = 声部色,亮度随追光强度 |
| 能量 `energy` | `0.16 + 0.34×近期命中率 + 0.24×min(1, 连击/24) + 0.065×已叠上的层数`;导演按能量自动换档(呼吸 → 律动 → 爆发,每档至少停 3 s)与镜头推进 |
| 漏拍 | `missDip`:灯总亮度 −45%,约 1.6 s 回升;能量也同步下压;连击清零 |
| 起承转合 | 第 1 段(只有鼓):能量低,"呼吸"档,舞台克制;每叠一层能量 +0.065,命中准则继续升;第 3~4 段进入"律动 → 爆发"并在触顶时出现"落点"(先黑 0.15 s 再炸开,沿用 v3 F9);完成时金色彩带与冲击波;打得差则一直停在低档,灯"跟着你走" |
| 频闪 | 沿用 v3 的 ≤ 3 次/秒上限与"减少动效"降级 |

## 10. 与「AI 复刻一首歌」的衔接路线

目标:用户**自带**一首歌(本地文件)→ 本地分析 → 生成一份 `lp-chart/1` 谱面 → 在跟打模式里一层层打出来。演示谱面的"鼓 → 贝斯 → 和弦 → 旋律"顺序,就是这条流水线的输出形态。

### 10.1 流水线草图

```
音频文件(用户自带,本机)
  ↓ 1 解码、重采样
  ↓ 2 分轨 ─────────────→ drums / bass / other(和声+旋律) / vocals
  ↓ 3 节拍·小节·速度 ───→ beats[], downbeats[], bpm(是否恒速)
  ↓ 4 调性·和弦 ────────→ key, 每小节和弦(根音)
  ↓ 5 转写 ─────────────→ 鼓:kick/snare/hat 起点;贝斯、旋律:音高+起止(MIDI)
  ↓ 6 谱面生成(本项目规则)
        · 量化到 1/8~1/16 拍,调内吸附(盘面是五声音阶)
        · 声部→行带(鼓 1 / 贝斯 2 / 和弦 3 / 旋律 4~5);列 = 轨道或音高桶
        · 难度裁剪:密度 ≤ 4 个/秒,同时 ≤ 2,同键间隔 ≥ 0.25 拍,低置信度先丢
        · 分段:按能量/自相似把歌切成 4~8 段,决定"哪一层在哪一段加入"
  ↓ 7 校验 + 试玩模拟(check_highway 的谱面规则 + 自动打手能通关)
  → lp-chart/1 JSON → 跟打模式
```

声音始终由**本产品自带合成器**发出(不回放原曲的音频),原曲只在本机分析。

## 11. 没做的、风险、需要用户拍板

**没做**:真人试玩与盲评(所有"直观/好看"的结论都是设计论证 + 几何指标 + 自评,**未经真人验证**);真机 Launchpad 联调(本原型的盘面是屏幕镜像,真机的灯刷新速率、按键到主机的延迟仍 [待验证],校准步骤正是为此准备);设备上进入跟打的专用键位(目前只能在屏幕上点「跟打」);MIDI/音频导入与谱面编辑器;重打本段/段落重试;变速曲(`tempoMap` 只是预留);把格阵画进 3D 舞台地面(需要专门机位,集成显卡代价 [待验证]);「用你的手感做 swing」。

**风险**:① 透视格阵 ↔ 设备的映射,小白第一次是否一眼能懂 [待验证];② 屏幕显示延迟(60 Hz 屏幕 + 浏览器)未单独测量,靠校准吸收;③ 3D 摇头灯光束与 2D 光斑的落点不是同一几何,只表达"这盏灯在追光";④ 演示谱面只有 91 个音、没有真正的同时光条,多追光分配只在自检里用合成数据验证过,尚未在真实密集谱面上看过。

**需要你拍板的 2 个问题**

1. **没叠上的那一层怎么办?** 现在是**静默**(强成就导向:你打出来才响,后面少一层你一听就知道缺了什么)。备选:(a) 乐队用**暗淡的垫底版**(音量 25%)接着响,降低挫败感,但"我复刻出来了"的对比会弱;(b) 允许**重打本段**。我倾向 (b) + 静默(保留成就感又不挫败),但这会让一首歌的时长变得不确定。
2. **"复刻一首歌"的第一步先做什么?** (a) **先做 MIDI 导入**(P2,不依赖 AI,稳,几周可成,用户要先有 .mid);(b) **直接做音频转写**(P3/P4,更接近"听到好听的歌就能打",但质量和耗时 [待验证],且受分轨/转写模型许可约束)。我推荐 (a) 先行,同时并行评估 (b) 的许可与质量。
